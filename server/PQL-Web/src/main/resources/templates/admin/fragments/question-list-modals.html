주요 규칙

  • JSON 파일은 배열 형태여야 합니다 [{...}, {...}]
  • 한 번에 최대 100건까지 가져올 수 있습니다
  • 내보내기는 최대 500건까지 지원합니다
  • questionUuid가 있으면 기존 문제를 업데이트, 없으면 신규 등록
  • questionUuid를 제거하면 복제/이관 용도로 활용 가능
  • EXECUTABLE 문제는 가져오기 시 Sandbox 자동 검증 (DDL + 샘플데이터 적용 후 answerSql 실행 테스트)
  • CONCEPT_ONLY 문제는 Sandbox 검증을 건너뜁니다 (SKIP)
  • 검증 후 "전체 등록" 또는 "성공한 것만 등록"을 선택할 수 있습니다

⚠️ stem SQL 마크다운 코드 블록 규칙

EXECUTABLE 문제에서 stem에 SQL이 포함될 경우 반드시 ```sql 코드 블록으로 감싸야 합니다. 화면에서 마크다운으로 렌더링되어 코드 블록으로 표시됩니다. 
// ❌ 잘못된 방식
"stem": "다음 SQL의 실행 결과로 올바른 것은?\\n\\nSELECT A.NAME FROM EMP;"

// ✅ 올바른 방식
"stem": "다음 SQL의 실행 결과로 올바른 것은?\\n\\n```sql\\nSELECT A.NAME FROM EMP;\\n```"

⚠️ 테이블 이름 작성 규칙

각 문제는 독립된 Sandbox(격리된 DB)에서 실행됩니다. 문제 간 테이블 이름 충돌이 없으므로, 시험 회차나 문제 번호를 테이블 이름에 포함할 필요가 없습니다. 
// ❌ 나쁜 예 — 시험 회차/문제 번호가 테이블명에 포함된 경우
"schemaDdl": "CREATE TABLE SQLD_14 (NUM INT, CODE VARCHAR(1));"

// ✅ 좋은 예 — 역할이 드러나는 짧고 명확한 이름
"schemaDdl": "CREATE TABLE EMP (EMP_ID INT, NAME VARCHAR(50));"  -- 임직원/인사
"schemaDdl": "CREATE TABLE T1 (COL1 INT, COL2 VARCHAR(1));"     -- 더미 데이터
