### 01-sql_window

**오답 · B 선택, 정답은 A · 총 4명의 직원 중 CHOI의 순위는 3위이므로 4가 될 수 없습니다.**

**정답 A 근거**
DENSE_RANK 함수는 동일한 순위 값을 가진 행에 대해 동일한 순위를 부여하고, 다음 순위는 연속적으로 부여합니다. SAL이 300인 KIM은 1위, SAL이 200인 LEE와 PARK는 공동 2위, SAL이 100인 CHOI는 3위가 됩니다.

**핵심 개념**
- **DENSE_RANK 함수**: 행 집합에서 현재 행의 순위를 계산합니다. 동일한 값에는 동일한 순위를 부여하고, 다음 순위는 연속적으로 부여합니다.
- **윈도우 함수**: 행 집합에 대해 계산을 수행하고 각 행에 대한 결과를 반환하는 함수입니다.

**헷갈리는 지점**
- RANK 함수와의 차이점: RANK 함수는 동일한 순위 값을 가진 행에 대해 동일한 순위를 부여하지만, 다음 순위는 순위 값의 차이만큼 건너뜁니다.

**보기별 판단**
- **A** (정답): SAL 기준 내림차순 정렬 시 CHOI는 3번째 그룹에 속하므로 DENSE_RANK는 3을 부여합니다.
- **B** (오답, 내 선택): 총 4명의 직원 중 CHOI의 순위는 3위이므로 4가 될 수 없습니다.
- **C** (오답): SAL이 200인 LEE와 PARK가 공동 2위이므로 CHOI의 순위는 2가 될 수 없습니다.
- **D** (오답): SAL이 가장 높은 KIM이 1위이므로 CHOI의 순위는 1이 될 수 없습니다.

**시험 팁** DENSE_RANK는 같은 순위를 부여하고 다음 순위를 건너뛰지 않음을 기억하세요.

### 02-sql_function

**오답 · B 선택, 정답은 A · 모든 SAL과 COMM 값을 단순히 더한 결과로, NULL 값 처리 방식을 고려하지 않았습니다.**

**정답 A 근거**
SUM 함수는 기본적으로 NULL 값을 제외하고 집계합니다. SAL + COMM 연산 시 NULL이 포함되면 결과는 NULL이 되지만, SUM 함수는 이 NULL 행을 제외하고 유효한 값만 더합니다. 따라서 100 + NULL = NULL (제외), 200 + 50 = 250, NULL + 30 = NULL (제외)이므로 최종 결과는 250입니다.

**핵심 개념**
- **NULL 값 처리**: SQL에서 NULL은 알 수 없는 값을 의미하며, 산술 연산 시 NULL을 포함하면 결과는 NULL이 됩니다. 집계 함수는 기본적으로 NULL을 제외하고 연산을 수행합니다.
- **SUM 함수**: SUM 함수는 숫자 데이터의 합계를 계산하는 집계 함수로, NULL 값을 제외하고 연산을 수행합니다.

**헷갈리는 지점**
- 산술 연산 시 NULL의 영향과 집계 함수 내 NULL 처리 방식의 차이
- SUM 함수가 NULL 행을 어떻게 처리하는지에 대한 오해

**보기별 판단**
- **A** (정답): SAL + COMM 연산 결과 중 NULL이 아닌 값(250)만 SUM 함수가 집계하여 올바른 결과입니다.
- **B** (오답, 내 선택): 모든 SAL과 COMM 값을 단순히 더한 결과로, NULL 값 처리 방식을 고려하지 않았습니다.
- **C** (오답): SAL 컬럼의 NULL 값을 0으로 간주하고 계산한 결과입니다.
- **D** (오답): SUM 함수가 NULL을 포함한 모든 행을 집계 결과에서 제외한다고 오해한 결과입니다.

**시험 팁** 집계 함수는 NULL을 제외하고 연산한다는 점을 기억하면 NULL 관련 문제를 쉽게 풀 수 있습니다.

### 03-sql_group_aggregate

**오답 · A 선택, 정답은 C · COUNT(BONUS)는 NULL을 제외하고 세므로, 보너스를 받은 사원 수만 집계합니다.**

**정답 C 근거**
COUNT(BONUS)는 NULL이 아닌 값만 세지만, COUNT(*)는 모든 행을 셉니다. 따라서 C는 부서별 총 사원 수를, 나머지는 보너스를 받은 사원 수를 세어 결과가 다릅니다.

**핵심 개념**
- **COUNT 함수**: COUNT(*)는 모든 행을, COUNT(컬럼)은 해당 컬럼의 NULL이 아닌 행만 셉니다.
- **CASE 문**: 조건에 따라 다른 값을 반환하며, 집계 함수와 함께 사용될 수 있습니다.

**헷갈리는 지점**
- COUNT(*)와 COUNT(컬럼)의 차이점: NULL 값을 포함하는지 여부
- COUNT(CASE WHEN ... THEN 1 END)와 COUNT(컬럼)의 유사점: NULL이 아닌 값만 세는 동작

**보기별 판단**
- **A** (오답, 내 선택): COUNT(BONUS)는 NULL을 제외하고 세므로, 보너스를 받은 사원 수만 집계합니다.
- **B** (오답): CASE 문을 사용하여 NULL이 아닌 경우 1을 세므로, 보너스를 받은 사원 수를 집계합니다.
- **C** (정답): COUNT(*)는 NULL 포함 모든 행을 세므로, 부서별 총 사원 수를 집계합니다.
- **D** (오답): CASE 문에서 NULL을 반환하는 경우를 제외하면 COUNT(BONUS)와 동일하게 동작합니다.

**시험 팁** COUNT(*)는 모든 행, COUNT(컬럼)은 NULL 제외 행을 센다는 점을 기억하세요.

### 04-sql_join

**오답 · A 선택, 정답은 B · EMP 테이블에서 DEPTNO가 NULL이 아닌 행의 개수만 센 결과입니다.**

**정답 B 근거**
LEFT OUTER JOIN은 왼쪽 테이블(DEPT)의 모든 행을 포함하고, 오른쪽 테이블(EMP)에서 조인 조건에 맞는 행을 연결합니다. DEPT 테이블은 3개의 행을 가지며, EMP 테이블은 DEPTNO가 10인 행 2개, 20인 행 1개와 매칭됩니다. DEPTNO가 30인 DEPT 행은 EMP 테이블에 매칭되는 행이 없어 NULL로 연결됩니다. 따라서 총 4개의 행이 생성되며, COUNT(*)는 4를 반환합니다.

**핵심 개념**
- **LEFT OUTER JOIN**: 왼쪽 테이블의 모든 행과 오른쪽 테이블의 일치하는 행을 반환합니다. 일치하는 행이 없으면 오른쪽 테이블의 컬럼은 NULL로 채워집니다.
- **COUNT(*)**: 조인 결과로 생성된 모든 행의 개수를 반환합니다. NULL 행도 포함됩니다.

**헷갈리는 지점**
- EMP 테이블의 NULL 값을 가진 행이 결과에 영향을 주는지 여부
- LEFT JOIN 시 DEPT 테이블의 모든 행이 결과에 포함되는지 여부

**보기별 판단**
- **A** (오답, 내 선택): EMP 테이블에서 DEPTNO가 NULL이 아닌 행의 개수만 센 결과입니다.
- **B** (정답): DEPT 테이블의 모든 행(3개)과 EMP 테이블의 매칭되는 행(3개) 및 매칭되지 않는 행(1개)을 포함한 총 4개의 행이 생성됩니다.
- **C** (오답): DEPT 테이블의 행 수(3개)와 EMP 테이블의 총 행 수(4개)를 단순히 더한 결과입니다.
- **D** (오답): DEPT 테이블에서 EMP 테이블과 매칭되는 행의 개수만 센 결과입니다.

**시험 팁** LEFT JOIN은 왼쪽 테이블 기준, NULL 포함 모든 행을 센다는 점을 기억하세요.

### 05-sql_basic_select

**오답 · B 선택, 정답은 A · UNION ALL을 사용했을 때의 결과 행 수이며, UNION은 중복을 제거합니다.**

**정답 A 근거**
`UNION` 연산자는 중복된 행을 제거합니다. 테이블 A의 `X` 값은 1, 2, 2이고 테이블 B의 `X` 값은 2, 3입니다. `UNION` 연산 후 결과는 1, 2, 3으로 중복이 제거된 3개의 행이 됩니다.

**핵심 개념**
- **UNION 연산자**: 두 개 이상의 SELECT 문의 결과를 결합하며, 기본적으로 중복된 행을 제거합니다.
- **중복 제거**: UNION 연산자는 결과 집합에서 중복된 행을 자동으로 제거하여 고유한 행만 반환합니다.

**헷갈리는 지점**
- `UNION ALL`과의 차이점: `UNION ALL`은 중복을 제거하지 않고 모든 행을 반환하므로, 이 경우 결과 행 수는 5가 됩니다.

**보기별 판단**
- **A** (정답): UNION 연산자로 인해 중복된 2가 제거되어 고유한 값 1, 2, 3만 남으므로 3행이 맞습니다.
- **B** (오답, 내 선택): UNION ALL을 사용했을 때의 결과 행 수이며, UNION은 중복을 제거합니다.
- **C** (오답): 테이블 A의 중복된 2를 제거하지 않고 합산한 결과입니다.
- **D** (오답): 테이블 B의 값만 고려한 결과입니다.

**시험 팁** UNION은 중복 제거, UNION ALL은 중복 포함을 기억하세요.

### 06-sql_subquery

**오답 · A 선택, 정답은 B · 정렬 전에 `ROWNUM = 1`이 적용되어 가장 높은 급여를 보장할 수 없습니다.**

**정답 B 근거**
서브쿼리에서 급여(SAL)를 기준으로 내림차순 정렬 후, 메인 쿼리에서 `ROWNUM = 1` 조건을 사용하여 가장 높은 급여를 받는 사원 1명을 정확히 추출합니다. 다른 보기는 `ROWNUM`의 동작 방식이나 집계 함수 사용 오류로 인해 올바른 결과를 보장하지 못합니다.

**핵심 개념**
- **ROWNUM 속성**: Oracle 에서 쿼리 결과 집합에 번호를 매기는 가상 컬럼. WHERE 절에서 사용 시 순서에 주의해야 함.
- **서브쿼리 (Subquery)**: 다른 SQL 문 안에 포함된 SELECT 문. 복잡한 조건이나 데이터 조작에 활용됨.
- **ORDER BY 절**: 결과 집합의 행을 지정한 컬럼 기준으로 정렬하는 절.

**헷갈리는 지점**
- `ROWNUM`은 `ORDER BY`보다 먼저 적용되므로, `ORDER BY`로 정렬된 결과에서 상위 1개를 가져오려면 반드시 서브쿼리를 사용해야 합니다.
- 최대값(MAX)과 최소값(MIN) 함수를 잘못 사용하면 의도와 다른 결과를 얻게 됩니다.

**보기별 판단**
- **A** (오답, 내 선택): 정렬 전에 `ROWNUM = 1`이 적용되어 가장 높은 급여를 보장할 수 없습니다.
- **B** (정답): 서브쿼리에서 정렬 후 `ROWNUM = 1`로 가장 높은 급여를 받는 사원 1명을 정확히 추출합니다.
- **C** (오답): 조건이 `ROWNUM = 2`로 설정되어 두 번째로 높은 급여를 받는 사원을 찾습니다.
- **D** (오답): `MIN(SAL)` 함수는 가장 낮은 급여를 찾는 것으로, 문제의 요구사항과 다릅니다.

**시험 팁** `ROWNUM`은 `ORDER BY`보다 먼저 적용되므로, 정렬 후 상위 N개를 원하면 반드시 서브쿼리를 활용하세요.

### 07-sql_hierarchy_pivot

**오답 · A 선택, 정답은 C · 'SCOTT'만 조회되어 1행이 나오는 것으로 잘못 판단한 경우입니다.**

**정답 C 근거**
계층 쿼리는 START WITH 절에서 시작하여 CONNECT BY 절 조건에 따라 상위 또는 하위 레벨의 데이터를 탐색합니다. 'SCOTT'부터 시작하여 상위 관리자(MGR)를 따라 올라가면 'JONES', 'KING' 순서로 총 3개의 행이 조회됩니다.

**핵심 개념**
- **계층 쿼리 (Hierarchical Query)**: START WITH, CONNECT BY 절을 사용하여 트리 구조의 데이터를 조회하는 SQL 기능입니다.
- **CONNECT BY 절**: 계층 구조에서 부모-자식 관계를 정의하여 데이터를 탐색하는 조건입니다. PRIOR 키워드로 탐색 방향을 지정합니다.

**헷갈리는 지점**
- CONNECT BY PRIOR MGR = EMPNO 조건은 'SCOTT'의 MGR(2)과 일치하는 EMPNO(2)를 가진 행을 찾는 것이 아니라, 현재 행의 MGR 값이 상위 행의 EMPNO 값과 일치하는 관계를 탐색합니다. 즉, 자식에서 부모로 올라가는 방향입니다.
- START WITH 절은 쿼리의 시작점을 지정하며, CONNECT BY 절은 이 시작점부터 계층 구조를 탐색합니다. 탐색 방향에 따라 결과 행 수가 달라집니다.

**보기별 판단**
- **A** (오답, 내 선택): 'SCOTT'만 조회되어 1행이 나오는 것으로 잘못 판단한 경우입니다.
- **B** (오답): 'SCOTT'와 'JONES'만 조회되어 2행이 나오는 것으로 잘못 판단한 경우입니다.
- **C** (정답): 'SCOTT' (3번 사원)부터 시작하여 상위 관리자(MGR)를 따라 올라가면 'JONES' (2번 사원), 'KING' (1번 사원)까지 총 3개의 행이 조회됩니다.
- **D** (오답): 'SCOTT'부터 시작하여 하위 사원까지 탐색하거나, 잘못된 계층 관계를 설정한 경우입니다.

**시험 팁** 계층 쿼리는 START WITH에서 시작해 CONNECT BY 조건으로 탐색 방향(상위/하위)을 파악하는 것이 중요합니다.

### 08-sql_ddl_dml_tcl

**오답 · A 선택, 정답은 B · ROLLBACK은 INSERT만 취소시키므로, T 테이블에는 데이터가 남아있어 0이 아니다.**

**정답 B 근거**
CREATE TABLE 문은 트랜잭션 제어와 무관하게 즉시 반영된다. ROLLBACK은 INSERT 문만 취소시키므로, 마지막 SELECT 결과는 1이다.

**핵심 개념**
- **DDL과 DML의 트랜잭션 처리 차이**: CREATE, ALTER, DROP 등 DDL은 실행 즉시 커밋되며 트랜잭션 롤백 대상이 아니다. INSERT, UPDATE, DELETE 등 DML은 트랜잭션 내에서 처리된다.
- **ROLLBACK의 동작 범위**: ROLLBACK은 DML 작업만 취소하며, DDL 작업으로 생성되거나 변경된 객체는 영향을 받지 않는다.

**헷갈리는 지점**
- DDL 문(CREATE TABLE)이 실행된 후 ROLLBACK 하면 해당 DDL 작업도 취소된다고 오해하기 쉽다.
- INSERT 문과 CREATE TABLE 문이 혼합된 경우, ROLLBACK이 어떤 작업에 영향을 미치는지 정확히 구분해야 한다.

**보기별 판단**
- **A** (오답, 내 선택): ROLLBACK은 INSERT만 취소시키므로, T 테이블에는 데이터가 남아있어 0이 아니다.
- **B** (정답): INSERT 후 CREATE TABLE, ROLLBACK 순서로 실행되면 INSERT만 취소되고 T 테이블에는 1이 남아있다.
- **C** (오답): DDL 문은 트랜잭션 제어와 무관하게 즉시 반영되므로 오류가 발생하지 않는다.
- **D** (오답): 테이블 T에는 1개의 행만 삽입되었고, ROLLBACK으로 취소되었으므로 2가 될 수 없다.

**시험 팁** DDL은 즉시 커밋되므로 ROLLBACK에 영향을 받지 않는다는 점을 기억하라.

### 01-sql_window

- **DENSE_RANK 함수**: 행 집합 내에서 현재 행의 순위를 반환하며, 동일한 값에 동일한 순위를 부여하고 다음 순위를 건너뛰지 않습니다.

- ORDER BY 절의 중요성: 윈도우 함수에서 ORDER BY 절은 순위 결정의 기준이 되므로 필수적입니다.

**시험 팁** DENSE_RANK는 순위를 건너뛰지 않으므로, 가장 낮은 값은 항상 전체 행 수보다 작거나 같은 순위를 갖습니다.

### 02-sql_function

**오답 · B 선택, 정답은 A · 모든 SAL 값(100, 200, NULL)과 COMM 값(NULL, 50, 30)을 단순히 더한 결과입니다. NULL이 포함된 연산은 무시해야 합니다.**

**정답 A 근거**
SUM 함수는 기본적으로 NULL 값을 제외하고 집계합니다. SAL + COMM 연산 시 NULL이 포함되면 결과가 NULL이 되지만, SUM 함수는 이 NULL 행을 제외하고 유효한 값만 더합니다. 따라서 100 + NULL = NULL (제외), 200 + 50 = 250, NULL + 30 = NULL (제외) 이므로 최종 결과는 250입니다.

**핵심 개념**
- **NULL 값 처리**: SQL 집계 함수는 기본적으로 NULL 값을 제외하고 연산을 수행합니다.
- **산술 연산과 NULL**: NULL과 어떤 값을 연산해도 결과는 NULL이 됩니다.

**헷갈리는 지점**
- SUM 함수가 NULL을 어떻게 처리하는지 혼동할 수 있습니다. SUM은 NULL 행을 제외하지만, 연산 중간에 NULL이 발생하면 해당 행은 집계에서 제외됩니다.
- SAL + COMM 연산 시 NULL이 포함된 행의 결과가 NULL이 된다는 점과 SUM 함수가 NULL 행을 제외한다는 점을 구분해야 합니다.

**보기별 판단**
- **A** (정답): SAL + COMM 연산 결과 중 NULL이 아닌 값(250)만 SUM 함수가 집계하여 250이 됩니다.
- **B** (오답, 내 선택): 모든 SAL 값(100, 200, NULL)과 COMM 값(NULL, 50, 30)을 단순히 더한 결과입니다. NULL이 포함된 연산은 무시해야 합니다.
- **C** (오답): SAL 값만 모두 더한 결과(100 + 200 = 300)입니다. COMM 값을 고려하지 않았습니다.
- **D** (오답): SUM 함수는 NULL을 제외하고 집계하므로, 유효한 값이 있으면 NULL이 아닌 결과가 나옵니다.

**시험 팁** SUM 함수는 NULL 행을 제외하고 집계합니다. 연산 중간에 NULL이 발생해도 해당 행은 집계에서 제외됩니다.

### 03-sql_group_aggregate

**오답 · A 선택, 정답은 C · COUNT(BONUS)는 DEPT별로 NULL이 아닌 BONUS 값의 개수를 셉니다. 결과: A:1, C:1**

**정답 C 근거**
COUNT(BONUS)는 NULL이 아닌 값만 집계하고, COUNT(*)는 모든 행을 집계합니다. 따라서 C는 모든 행을 세어 결과가 다릅니다. A와 D는 COUNT(컬럼)과 COUNT(CASE WHEN 컬럼 IS NOT NULL THEN 1 END)로 동일하게 NULL이 아닌 값만 집계합니다. B는 명시적으로 NULL이 아닌 경우만 1로 집계하여 COUNT(BONUS)와 동일한 결과를 냅니다.

**핵심 개념**
- **COUNT 함수**: COUNT 함수는 행의 개수를 세는 함수입니다. COUNT(*)는 모든 행을, COUNT(컬럼)은 해당 컬럼의 NULL이 아닌 행만 집계합니다.
- **NULL 값 처리**: 집계 함수 중 COUNT(컬럼)은 NULL 값을 제외하지만, COUNT(*)는 NULL 값을 포함하여 모든 행을 집계합니다.

**헷갈리는 지점**
- COUNT(*)와 COUNT(컬럼)의 차이: COUNT(*)는 모든 행을 세지만, COUNT(컬럼)은 해당 컬럼의 NULL이 아닌 행만 셉니다.
- CASE 표현식과 COUNT 함수의 조합: COUNT(CASE WHEN 조건 THEN 1 END)는 조건에 맞는 행만 집계하므로 COUNT(컬럼)과 유사하게 동작합니다.

**보기별 판단**
- **A** (오답, 내 선택): COUNT(BONUS)는 DEPT별로 NULL이 아닌 BONUS 값의 개수를 셉니다. 결과: A:1, C:1
- **B** (오답): SUM(CASE WHEN BONUS IS NOT NULL THEN 1 ELSE 0 END)는 NULL이 아닌 BONUS의 개수를 세어 COUNT(BONUS)와 동일한 결과를 냅니다. 결과: A:1, C:1
- **C** (정답): COUNT(*)는 DEPT별로 모든 행의 개수를 셉니다. 결과: A:2, B:2, C:1
- **D** (오답): COUNT(CASE WHEN BONUS IS NOT NULL THEN 1 END)는 NULL이 아닌 BONUS의 개수를 세어 COUNT(BONUS)와 동일한 결과를 냅니다. 결과: A:1, C:1

**시험 팁** COUNT(*)는 모든 행, COUNT(컬럼)은 NULL 아닌 값만 센다는 점을 기억하세요.

### 04-sql_join

- EMP 테이블의 NULL 값을 가진 행이 조인 결과에 영향을 주는지 여부
- LEFT JOIN과 INNER JOIN의 차이점

**보기별 판단**
- **A** (오답, 내 선택): DEPT 테이블의 행 수만 세었을 때의 결과입니다. EMP 테이블과의 조인을 고려하지 않았습니다.

### 05-sql_basic_select

**오답 · B 선택, 정답은 A · 모든 행의 합(5개)은 UNION ALL 연산자의 결과이며, UNION은 중복을 제거합니다.**

**정답 A 근거**
`UNION` 연산자는 중복된 행을 제거합니다. 테이블 A의 `X` 값은 1, 2, 2이고 테이블 B의 `X` 값은 2, 3입니다. `UNION` 후 결과는 1, 2, 3으로, 총 3개의 행이 됩니다.

**핵심 개념**
- **UNION 연산자**: 두 개 이상의 SELECT 문의 결과를 결합하며 중복된 행을 제거합니다.
- **중복 제거**: UNION은 기본적으로 DISTINCT 동작을 수행하여 결과 집합에서 중복을 허용하지 않습니다.

**헷갈리는 지점**
- UNION과 UNION ALL의 차이: UNION은 중복을 제거하지만, UNION ALL은 중복을 포함한 모든 행을 반환합니다.
- 중복된 행의 처리: 테이블 A에 있는 중복된 '2'가 결과에 어떻게 반영되는지 혼동할 수 있습니다.

**보기별 판단**
- **A** (정답): UNION 연산자는 중복을 제거하므로, A의 (1, 2, 2)와 B의 (2, 3)을 합치면 (1, 2, 3)이 되어 총 3개의 행입니다.
- **B** (오답, 내 선택): 모든 행의 합(5개)은 UNION ALL 연산자의 결과이며, UNION은 중복을 제거합니다.
- **C** (오답): 테이블 A의 모든 행(3개)과 테이블 B의 고유한 행(2, 3)을 합친 결과로, UNION의 동작 방식과 다릅니다.
- **D** (오답): 테이블 B의 고유한 행만 선택한 결과이며, 테이블 A의 값들을 고려하지 않았습니다.

**시험 팁** UNION은 중복 제거! 각 테이블의 고유값만 모아 개수를 세세요.

### 06-sql_subquery

**오답 · A 선택, 정답은 B · 정렬 전에 `ROWNUM = 1`이 적용되어 가장 높은 급여를 가진 사원이 아닐 수 있습니다.**

**정답 B 근거**
서브쿼리에서 급여(SAL)를 기준으로 내림차순 정렬 후, 메인 쿼리에서 `ROWNUM = 1` 조건을 사용하여 가장 높은 급여를 가진 사원 1명을 정확히 선택합니다. 다른 보기는 `ROWNUM`의 동작 방식이나 `MIN` 함수 사용으로 인해 올바른 결과를 보장하지 못합니다.

**핵심 개념**
- **ROWNUM 속성**: Oracle 에서 쿼리 결과 집합에 반환되는 행 번호. `ORDER BY` 절과 함께 사용할 때 주의 필요.
- **서브쿼리 활용**: 복잡한 조건이나 순서가 필요한 조회 시, 서브쿼리를 사용하여 단계별로 데이터를 처리하는 기법.

**헷갈리는 지점**
- `ROWNUM`은 `ORDER BY`보다 먼저 적용되므로, `ORDER BY` 절이 포함된 쿼리에 직접 `ROWNUM = 1`을 사용하면 의도한 결과가 나오지 않을 수 있습니다. 반드시 서브쿼리를 사용해야 합니다.
- 최대값(MAX)을 구하는 것이 문제의 요구사항인데, 오답 D는 최소값(MIN)을 구하여 틀렸습니다.

**보기별 판단**
- **A** (오답, 내 선택): 정렬 전에 `ROWNUM = 1`이 적용되어 가장 높은 급여를 가진 사원이 아닐 수 있습니다.
- **B** (정답): 서브쿼리에서 먼저 정렬한 후 `ROWNUM = 1`을 적용하여 가장 높은 급여를 가진 사원을 정확히 선택합니다.
- **C** (오답): `ROWNUM = 2` 조건은 두 번째로 높은 급여를 가진 사원을 선택하므로 틀렸습니다.
- **D** (오답): `MIN(SAL)` 함수는 가장 낮은 급여를 찾는 데 사용되므로 문제의 요구사항과 다릅니다.

**시험 팁** `ROWNUM`은 `ORDER BY`와 함께 쓸 때 서브쿼리를 활용해야 원하는 순서대로 행을 선택할 수 있습니다.

### 07-sql_hierarchy_pivot

**오답 · A 선택, 정답은 C · 'SCOTT' 행만 조회되어 1이 됩니다. 상위 행 탐색이 누락되었습니다.**

**정답 C 근거**
계층 쿼리는 START WITH 절의 조건에 맞는 행부터 시작하여 CONNECT BY 절의 조건에 따라 상위 또는 하위 행을 탐색합니다. 'SCOTT'부터 시작하여 상위 관리자(MGR)를 따라가면 'JONES', 'KING'까지 총 3개의 행이 조회됩니다.

**핵심 개념**
- **계층 쿼리 (Hierarchical Query)**: START WITH, CONNECT BY 절을 사용하여 트리 구조의 데이터를 조회하는 SQL 기능입니다.
- **START WITH 절**: 계층 쿼리의 시작점을 지정합니다. 지정된 행부터 탐색이 시작됩니다.
- **CONNECT BY 절**: 계층 구조를 탐색하는 규칙을 정의합니다. PRIOR 키워드를 사용하여 부모-자식 관계를 지정합니다.

**헷갈리는 지점**
- CONNECT BY PRIOR MGR = EMPNO 는 자식에서 부모를 찾는 조건입니다. START WITH 의 'SCOTT' 행(EMPNO=3)에서 시작하여 MGR=2인 상위 행(JONES)을 찾고, 다시 MGR=1인 상위 행(KING)을 찾는 방식입니다.
- CONNECT BY PRIOR EMPNO = MGR 조건과 혼동하기 쉽습니다. PRIOR EMPNO = MGR 은 부모에서 자식을 찾는 조건입니다.

**보기별 판단**
- **A** (오답, 내 선택): 'SCOTT' 행만 조회되어 1이 됩니다. 상위 행 탐색이 누락되었습니다.
- **B** (오답): 'SCOTT'와 'JONES'만 조회되어 2가 됩니다. 'KING' 행 탐색이 누락되었습니다.
- **C** (정답): 'SCOTT', 'JONES', 'KING' 세 행이 조회되어 3이 됩니다. 올바른 상위 행 탐색 결과입니다.
- **D** (오답): 'SCOTT', 'JONES', 'KING', 'BLAKE' 네 행이 조회되어 4가 됩니다. 'BLAKE'는 'SCOTT'의 상위 행이 아닙니다.

**시험 팁** START WITH 행부터 시작하여 CONNECT BY 조건으로 상위 또는 하위 행을 따라가며 개수를 센다.

### 08-sql_ddl_dml_tcl

**오답 · A 선택, 정답은 B · ROLLBACK은 DDL인 CREATE TABLE 문에 영향을 주지 않으므로 T 테이블의 데이터는 삭제되지 않는다.**

**정답 B 근거**
CREATE TABLE 문은 트랜잭션과 무관하게 즉시 반영된다. ROLLBACK은 DML인 INSERT만 취소하므로, T 테이블에는 여전히 1건의 데이터가 존재한다.

**핵심 개념**
- **DDL과 DML의 트랜잭션 처리 차이**: CREATE, ALTER, DROP 등 DDL은 실행 즉시 커밋되며 ROLLBACK 대상이 아니다. INSERT, UPDATE, DELETE 등 DML은 트랜잭션 내에서 처리된다.
- **ROLLBACK의 동작 범위**: ROLLBACK은 DML 문에 의해 변경된 내용을 취소한다. DDL 문 실행 결과는 취소되지 않는다.

**헷갈리는 지점**
- CREATE TABLE 문이 ROLLBACK으로 취소될 것이라는 오해.
- ROLLBACK이 DDL 문에도 영향을 미칠 것이라는 오해.

**보기별 판단**
- **A** (오답, 내 선택): ROLLBACK은 DDL인 CREATE TABLE 문에 영향을 주지 않으므로 T 테이블의 데이터는 삭제되지 않는다.
- **B** (정답): INSERT는 ROLLBACK으로 취소되지만, CREATE TABLE은 즉시 반영되어 T 테이블에는 1건의 데이터가 남는다.
- **C** (오답): DDL 문은 트랜잭션 제어와 무관하게 즉시 실행되므로 오류가 발생하지 않는다.
- **D** (오답): T 테이블에는 최대 1건의 데이터만 삽입되었고, ROLLBACK으로 취소되었으므로 2건이 될 수 없다.

**시험 팁** DDL은 실행 즉시 반영되고 ROLLBACK되지 않음을 기억하라.

### 09-data_modeling

**오답 · B 선택, 정답은 A · 이행적 함수 종속 제거는 제3정규형의 목표이며, 제2정규형과는 다릅니다.**

**정답 A 근거**
제2정규형은 기본키가 아닌 속성이 기본키 전체에 완전 함수 종속되어야 부분 함수 종속이 제거됩니다. 이는 기본키가 복합키일 때 부분 함수 종속을 해소하는 과정입니다.

**핵심 개념**
- **제2정규형 (2NF)**: 부분 함수 종속을 제거하여 기본키가 아닌 모든 속성이 기본키 전체에 완전 함수 종속되도록 하는 정규형
- **부분 함수 종속**: 복합 기본키의 일부에만 종속되는 현상
- **완전 함수 종속**: 기본키 전체에 종속되는 함수 종속

**헷갈리는 지점**
- 제2정규형은 부분 함수 종속 제거, 제3정규형은 이행적 함수 종속 제거에 초점
- 제1정규형은 반복 그룹 제거, 제4정규형은 다치 종속 제거에 초점

**보기별 판단**
- **A** (정답): 제2정규형은 부분 함수 종속을 제거하여 기본키 전체에 완전 함수 종속을 만족시키는 것을 목표로 합니다.
- **B** (오답, 내 선택): 이행적 함수 종속 제거는 제3정규형의 목표이며, 제2정규형과는 다릅니다.
- **C** (오답): 반복 그룹 제거는 제1정규형의 목표이며, 제2정규형과는 관련이 없습니다.
- **D** (오답): 모든 결정자가 후보키가 되도록 분해하는 것은 제3정규형 또는 BCNF의 목표이며, 제2정규형과는 다릅니다.

**시험 팁** 제2정규형은 '부분 함수 종속' 제거, 제3정규형은 '이행적 함수 종속' 제거를 떠올리세요.

### 02-sql_function

**오답 · B 선택, 정답은 A · 모든 값을 단순 합산한 오답**

**정답 A 근거**
산술 연산에서 `NULL`이 포함된 행은 연산 결과가 `NULL`이 되어 `SUM` 집계 함수에서 제외됩니다. ID 1은 `100 + NULL`로 `NULL`, ID 3은 `NULL + 30`으로 `NULL`이 되어 제외되고, ID 2만 `200 + 50`인 `250`으로 계산되어 총합은 `250`입니다.

**핵심 개념**
- **산술 연산과 NULL**: 숫자형 컬럼에 `NULL`이 포함된 상태로 산술 연산을 수행하면 전체 결과는 `NULL`이 됨
- **집계 함수의 NULL 처리**: `SUM` 등의 집계 함수는 계산 결과가 `NULL`인 행을 자동으로 집계에서 제외함

**헷갈리는 지점**
- 개별 컬럼의 `NULL`을 `0`으로 치환하지 않고 연산하면 전체 수식이 `NULL`로 평가됨
- `SUM(SAL) + SUM(COMM)`과 `SUM(SAL + COMM)`의 결과가 다를 수 있음을 혼동함

**보기별 판단**
- **A** (정답): ID 2의 계산 결과인 250만 집계됨
- **B** (오답, 내 선택): 모든 값을 단순 합산한 오답
- **C** (오답): NULL을 0으로 잘못 가정하여 계산한 오답
- **D** (오답): 전체 결과가 NULL이라고 착각한 오답

**시험 팁** 산술 연산 중 `NULL`은 결과를 `NULL`로 만들고 `SUM`은 이를 제외한다는 점을 기억할 것

### 03-sql_group_aggregate

**오답 · A 선택, 정답은 C · `COUNT(BONUS)`는 `NULL`을 제외한 보너스 수령 사원 수만 집계함**

**정답 C 근거**
`COUNT(*)`는 `NULL`을 포함한 전체 행 수를 세기 때문에 보너스가 `NULL`인 부서도 행 수로 집계됩니다. 반면 `COUNT(BONUS)`는 `NULL`을 제외하고 집계하므로 두 쿼리의 실행 결과는 다릅니다.

**핵심 개념**
- **COUNT 함수와 NULL**: `COUNT(*)`는 전체 행 수를 반환하고, `COUNT(열 이름)`은 `NULL` 값을 제외한 행 수를 반환합니다.

**헷갈리는 지점**
- `COUNT(*)`와 `COUNT(컬럼)`이 항상 같은 결과를 낼 것이라고 오해하는 점

**보기별 판단**
- **A** (오답, 내 선택): `COUNT(BONUS)`는 `NULL`을 제외한 보너스 수령 사원 수만 집계함
- **B** (오답): `CASE WHEN`으로 `NULL`이 아닌 경우만 `1`을 부여해 합산하므로 보너스 수령 사원 수를 구함
- **C** (정답): `COUNT(*)`는 `NULL`인 행까지 포함하여 부서별 전체 행 수를 집계함
- **D** (오답): `CASE` 식의 결과가 `NULL`인 행을 `COUNT`가 제외하므로 보너스 수령 사원 수를 구함

**시험 팁** COUNT 함수의 인자로 컬럼이 오면 NULL이 제외되고, *가 오면 전체 행이 집계됨

### 04-sql_join

**오답 · A 선택, 정답은 B · DEPT 테이블의 기본 행 수인 3으로 착각한 오답**

**정답 B 근거**
`LEFT OUTER JOIN`은 좌측 테이블인 `DEPT`의 모든 행을 기준으로 우측 `EMP` 테이블과 조인한다. `DEPT`의 `10`, `20`번 부서는 매칭되는 `EMP` 행 수만큼 확장되고, 매칭이 없는 `30`번 부서는 `EMP` 컬럼이 `NULL`인 1개 행으로 보존된다. 따라서 조인 결과 총 행 수는 4개가 되며 `COUNT(*)`는 전체 행 수를 반환한다.

**핵심 개념**
- **LEFT OUTER JOIN**: 좌측 테이블의 모든 행을 포함하고 우측 테이블은 조건에 맞는 행만 연결하며 없으면 NULL로 채움
- **COUNT(*)**: NULL을 포함한 조인 결과의 전체 행 수를 집계

**헷갈리는 지점**
- LEFT OUTER JOIN 결과를 EMP 테이블 기준으로 생각하여 매칭되는 3행만 카운트하는 실수
- DEPTNO가 NULL인 EMP 테이블의 4번 사원 행이 조인 결과에 포함될 것이라 오인하는 경우

**보기별 판단**

- **B** (정답): LEFT OUTER JOIN 결과 총 4개 행이 생성되므로 올바른 집계 값

- **D** (오답): 일치하는 행만 카운트하여 INNER JOIN 결과로 오인한 값

**시험 팁** LEFT OUTER JOIN의 결과 행 수는 좌측 테이블의 행 수 이상이다.

### 09-data_modeling

**오답 · B 선택, 정답은 A · 기본키가 아닌 속성 사이의 이행적 함수 종속을 제거하는 것은 제3정규형에 해당함**

**핵심 개념**

**헷갈리는 지점**
- 제2정규형(부분 함수 종속 제거)과 제3정규형(이행적 함수 종속 제거)의 대상과 개념을 혼동하기 쉬움

**보기별 판단**
- **A** (정답): 제2정규형의 정의인 부분 함수 종속 제거와 완전 함수 종속 만족을 정확히 설명함
- **B** (오답, 내 선택): 기본키가 아닌 속성 사이의 이행적 함수 종속을 제거하는 것은 제3정규형에 해당함
- **C** (오답): 모든 속성 값이 원자값이 되도록 반복 그룹을 제거하는 것은 제1정규형에 해당함
- **D** (오답): 모든 결정자가 후보키가 되도록 하는 것은 Boyce-Codd 정규형(BCNF)에 해당함

**시험 팁** 정규화 단계별 제거 대상(1NF: 반복그룹, 2NF: 부분함수종속, 3NF: 이행적함수종속, BCNF: 결정자이면서 후보키가 아닌 것)을 암기할 것

### 02-sql_function

### 03-sql_group_aggregate

**오답 · A 선택, 정답은 C · `COUNT(BONUS)`는 `NULL`을 제외하여 부서별 보너스 수령자 수를 정확히 구함**

- **CASE WHEN 조건 집계**: `NULL`이 아닌 경우만 1을 부여하고 나머지는 제외하여 보너스 수령자 수를 셀 수 있습니다.

**헷갈리는 지점**
- COUNT(*)과 COUNT(열이름)의 NULL 처리 차이
- CASE 문에서 ELSE 생략 시 NULL 반환 여부

**보기별 판단**
- **A** (오답, 내 선택): `COUNT(BONUS)`는 `NULL`을 제외하여 부서별 보너스 수령자 수를 정확히 구함
- **B** (오답): `CASE` 문으로 `NULL`이 아닌 행만 1로 더해 부서별 수령자 수를 정확히 구함
- **C** (정답): `COUNT(*)`은 `NULL`인 행도 포함하여 세므로 보너스 수령자 수가 아닌 전체 사원 수가 나옴
- **D** (오답): `COUNT(CASE ... END)`는 조건에 맞는 행만 세므로 보너스 수령자 수를 정확히 구함

**시험 팁** COUNT(*)은 NULL 포함 전체 행, COUNT(열)은 NULL 제외 행을 센다는 점을 확인하세요.

- COUNT(컬럼명)과 달리 COUNT(*)는 조인 결과로 생성된 전체 행 수를 그대로 카운트함.

**보기별 판단**

- **C** (오답): EMP 테이블의 NULL 부서 행까지 잘못 포함하여 계산한 오답임.
- **D** (오답): 조인 결과 행 수보다 적게 산정된 오답임.

### 05-sql_basic_select

### 08-sql_ddl_dml_tcl

**오답 · A 선택, 정답은 B · DDL 수행으로 자동 커밋이 발생하여 ROLLBACK이 INSERT를 취소하지 못하므로 0이 아님**

**정답 B 근거**
DML 문장인 `INSERT` 수행 직후 DDL 문장인 `CREATE TABLE`을 실행하면 자동 커밋이 발생한다. 따라서 이후에 `ROLLBACK`을 실행해도 `INSERT` 작업은 취소되지 않으므로 테이블 T에는 1개의 행이 남아있다.

**핵심 개념**
- **자동 커밋**: DDL 문장(`CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE`)이 실행되면 이전의 트랜잭션은 자동으로 커밋됨.
- **ROLLBACK**: 커밋되지 않은 트랜잭션의 변경 사항을 취소하는 DCL 명령어.

**헷갈리는 지점**
- DML 문장 뒤에 DDL 문장이 오면 트랜잭션이 자동 종료(커밋)된다는 점을 놓치기 쉬움
- ROLLBACK을 호출하면 모든 이전 작업이 무조건 취소된다고 오해하기 쉬움

**보기별 판단**
- **A** (오답, 내 선택): DDL 수행으로 자동 커밋이 발생하여 ROLLBACK이 INSERT를 취소하지 못하므로 0이 아님
- **B** (정답): DDL 실행으로 인한 자동 커밋 덕분에 INSERT가 유지되어 행 개수 1이 정상 출력됨
- **C** (오답): 문법적 오류나 실행 상의 에러를 유발하는 구문은 포함되어 있지 않음
- **D** (오답): INSERT는 한 번만 수행되었으므로 행 개수가 2가 될 수 없음

**시험 팁** DML 다음 DDL이 나오면 그 즉시 자동 커밋이 일어남을 기억할 것

### 09-data_modeling

**오답 · B 선택, 정답은 A · 기본키가 아닌 속성 사이의 이행적 함수 종속 제거는 제3정규형의 설명**

**정답 A 근거**
제2정규형은 제1정규형을 만족하고, 기본키의 진부분집합이 결정자 역할을 하는 부분 함수 종속을 제거하여 기본키 전체에 완전 함수 종속되도록 테이블을 분해하는 단계이다. 이를 통해 복합 기본키의 일부 컬럼에만 종속되는 데이터의 이상 현상을 방지한다.

**핵심 개념**
- **제2정규형(2NF)**: 부분 함수 종속을 제거하고 완전 함수 종속을 만족하는 정규화 단계
- **완전 함수 종속**: 기본키 전체에 종속되며, 기본키의 일부분에 종속되지 않는 상태

**헷갈리는 지점**
- 제2정규형의 부분 함수 종속 제거와 제3정규형의 이행적 함수 종속 제거 개념 혼동

**보기별 판단**
- **A** (정답): 부분 함수 종속을 제거하고 완전 함수 종속을 만족하는 제2정규형의 올바른 설명
- **B** (오답, 내 선택): 기본키가 아닌 속성 사이의 이행적 함수 종속 제거는 제3정규형의 설명
- **C** (오답): 반복 그룹을 제거하고 원자값을 만드는 것은 제1정규형의 설명
- **D** (오답): 모든 결정자가 후보키가 되도록 하는 것은 BCNF의 설명
