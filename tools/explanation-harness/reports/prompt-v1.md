### 01-sql_window

**오답 · B 선택, 정답은 A · 4 는 `RANK` 기준 순위**

**정답 A 근거**
`DENSE_RANK` 는 동점에 같은 순위를 주고 다음 순위를 건너뛰지 않음. KIM 1, LEE·PARK 동점 2, CHOI 는 바로 다음 3.

**핵심 개념**
- **DENSE_RANK**: 동점 같은 순위, 다음 순위는 1 증가 (1, 2, 2, 3)
- **RANK**: 동점 같은 순위, 동점 수만큼 다음 순위 건너뜀 (1, 2, 2, 4)

**헷갈리는 지점**
- `RANK` 와 `DENSE_RANK` 는 동점 다음 순위만 다름
- `ROW_NUMBER` 는 동점이어도 1, 2, 3, 4 로 모두 다른 번호

**보기별 판단**
- **A** (정답): 동점 2위 2명 뒤 순위를 건너뛰지 않아 3
- **B** (오답, 내 선택): 4 는 `RANK` 기준 순위
- **C** (오답): 2 는 동점인 LEE·PARK 의 순위
- **D** (오답): 1 은 최고 급여 KIM 의 순위

**시험 팁** 동점 바로 다음 행의 순위 번호로 세 함수 구분

### 02-sql_function

**오답 · B 선택, 정답은 A · 380 은 `SUM(SAL) + SUM(COMM)` 값**

**정답 A 근거**
`SAL + COMM` 은 한쪽이 NULL 이면 NULL. 1번(100+NULL)·3번(NULL+30) 행은 NULL, 2번 행만 250. `SUM` 은 NULL 을 제외해 250.

**핵심 개념**
- **NULL 산술 연산**: NULL 과 사칙연산 결과는 항상 NULL
- **집계 함수와 NULL**: `SUM`·`AVG`·`COUNT(컬럼)` 은 NULL 행 제외

**헷갈리는 지점**
- `SUM(SAL) + SUM(COMM)` 은 열별로 NULL 을 먼저 빼고 더해 380
- NULL 이 섞여도 `SUM` 결과 전체가 NULL 이 되지는 않음

**보기별 판단**
- **A** (정답): 행 단위 덧셈 후 NULL 제외 합계 250
- **B** (오답, 내 선택): 380 은 `SUM(SAL) + SUM(COMM)` 값
- **C** (오답): 300 은 SAL 합계만 더한 값
- **D** (오답): `SUM` 은 NULL 행을 건너뛰어 NULL 아님

**시험 팁** 행 안 연산이 먼저, 집계는 그다음. NULL 섞인 행부터 표시

### 03-sql_group_aggregate

**오답 · A 선택, 정답은 C · 기준과 같은 `COUNT(BONUS)`, A 1, B 0, C 1**

**정답 C 근거**
문제는 결과가 다른 SQL 을 묻는 유형. `COUNT(*)` 는 NULL 행까지 세어 A 2, B 2, C 1. 나머지 세 SQL 은 모두 A 1, B 0, C 1.

**핵심 개념**
- **COUNT(*) vs COUNT(컬럼)**: `COUNT(*)` 는 행 수 전체, `COUNT(컬럼)` 은 NULL 아닌 값만
- **CASE 와 COUNT**: ELSE 없는 `CASE` 는 조건 거짓이면 NULL, `COUNT` 에서 빠짐

**헷갈리는 지점**
- '다른 것'을 묻는 문제라 정답은 틀린 집계를 하는 SQL
- `SUM(CASE ... ELSE 0 END)` 은 B 부서도 0 으로 남아 결과 동일

**보기별 판단**
- **A** (오답, 내 선택): 기준과 같은 `COUNT(BONUS)`, A 1, B 0, C 1
- **B** (오답): NULL 아닌 행만 1 로 더해 같은 결과
- **C** (정답): NULL 행까지 세어 A 2, B 2 로 결과가 다름
- **D** (오답): 거짓이면 NULL 이 되어 `COUNT` 에서 빠져 같은 결과

**시험 팁** NULL 있는 컬럼은 `COUNT(*)` 와 `COUNT(컬럼)` 결과부터 비교

### 04-sql_join

**오답 · A 선택, 정답은 B · 3 은 짝 없는 SALES 를 뺀 `INNER JOIN` 행 수**

**정답 B 근거**
`LEFT OUTER JOIN` 은 왼쪽 DEPT 행을 모두 남김. ACC 2행, RES 1행, 짝 없는 SALES 도 EMP 쪽 NULL 로 1행, 합계 4.

**핵심 개념**
- **LEFT OUTER JOIN**: 왼쪽 테이블 행 전부 유지, 짝 없으면 오른쪽 컬럼 NULL
- **NULL 조인 조건**: `DEPTNO` 가 NULL 인 사원 4 는 어떤 부서와도 같지 않음

**헷갈리는 지점**
- 부서 없는 사원 4 는 오른쪽에만 있어 `LEFT` 결과에 안 나옴
- `FULL OUTER JOIN` 이면 사원 4 까지 더해 5

**보기별 판단**
- **A** (오답, 내 선택): 3 은 짝 없는 SALES 를 뺀 `INNER JOIN` 행 수
- **B** (정답): DEPT 3개 전부 유지, ACC 2행 포함 4
- **C** (오답): 5 는 `FULL OUTER JOIN` 행 수
- **D** (오답): 2 는 사원이 있는 부서 수일 뿐

**시험 팁** 기준 테이블 행 수 + 1:N 으로 늘어난 행 수로 계산

### 05-sql_basic_select

**오답 · B 선택, 정답은 A · 5 는 `UNION ALL` 행 수**

**정답 A 근거**
`UNION` 은 두 결과를 합친 뒤 중복 제거. A 의 1, 2, 2 와 B 의 2, 3 에서 중복 2 를 한 번만 남겨 1, 2, 3 세 행.

**핵심 개념**
- **UNION**: 합집합 후 중복 행 제거 (정렬 비용 발생 가능)
- **UNION ALL**: 중복 포함 그대로 합침

**헷갈리는 지점**
- 같은 테이블 안 중복(A 의 2, 2)도 `UNION` 에서 제거
- `UNION ALL` 이면 3 + 2 = 5행

**보기별 판단**
- **A** (정답): 중복 제거 후 1, 2, 3 세 행
- **B** (오답, 내 선택): 5 는 `UNION ALL` 행 수
- **C** (오답): A 안 중복을 남긴 잘못된 계산
- **D** (오답): 2 는 근거 없는 값, 공통 값은 2 하나

**시험 팁** `UNION` 은 결과 전체 기준 중복 제거, 테이블 안 중복도 포함

### 06-sql_subquery

**오답 · A 선택, 정답은 B · 정렬 전에 첫 행 A 를 자른 뒤 정렬**

**정답 B 근거**
인라인 뷰에서 `ORDER BY SAL DESC` 로 먼저 정렬한 뒤 바깥에서 `ROWNUM = 1` 을 잘라 최고 급여 B 만 남김.

**핵심 개념**
- **ROWNUM**: WHERE 단계에서 행을 가져오는 순서대로 1부터 부여, `ORDER BY` 보다 먼저
- **Top-N 질의**: 인라인 뷰 정렬 후 바깥 `ROWNUM <= N`

**헷갈리는 지점**
- 같은 쿼리의 `ORDER BY` 는 `ROWNUM` 부여 뒤 실행
- `ROWNUM = 2` 는 첫 행이 1 을 못 받아 항상 0행

**보기별 판단**
- **A** (오답, 내 선택): 정렬 전에 첫 행 A 를 자른 뒤 정렬
- **B** (정답): 정렬 후 첫 행을 잘라 최고 급여 B
- **C** (오답): `ROWNUM = 2` 조건은 항상 0행
- **D** (오답): `MIN` 이라 최저 급여 A

**시험 팁** `ROWNUM` 과 `ORDER BY` 가 같은 층이면 오답 후보

### 07-sql_hierarchy_pivot

**오답 · A 선택, 정답은 C · 1 은 순방향일 때 SCOTT 만 남는 경우**

**정답 C 근거**
`CONNECT BY PRIOR MGR = EMPNO` 는 현재 행의 MGR 을 EMPNO 로 가진 상위 행으로 이동하는 역방향 전개. SCOTT > JONES > KING 3행.

**핵심 개념**
- **CONNECT BY PRIOR**: `PRIOR` 가 붙은 쪽이 이미 읽은 행, 반대쪽이 다음에 찾을 행
- **순방향·역방향**: `PRIOR EMPNO = MGR` 은 부하 방향, `PRIOR MGR = EMPNO` 는 관리자 방향

**헷갈리는 지점**
- `PRIOR` 위치만 바뀌어도 전개 방향이 반대
- `START WITH` 행도 결과 1행으로 포함

**보기별 판단**
- **A** (오답, 내 선택): 1 은 순방향일 때 SCOTT 만 남는 경우
- **B** (오답): KING 까지 올라가지 않은 계산
- **C** (정답): SCOTT, JONES, KING 3행
- **D** (오답): 4 는 KING 에서 순방향 전체 전개

**시험 팁** `PRIOR` 붙은 컬럼 = 지금 행, 그 값으로 다음 행 찾기

### 08-sql_ddl_dml_tcl

**오답 · A 선택, 정답은 B · DDL 자동 커밋을 놓쳐 INSERT 취소로 본 값**

**정답 B 근거**
Oracle 에서 `CREATE TABLE` 같은 DDL 은 실행 전 자동 커밋. 앞선 INSERT 가 확정되어 `ROLLBACK` 으로 취소되지 않아 1.

**핵심 개념**
- **DDL 자동 커밋**: Oracle DDL 은 실행 전후 암묵적 COMMIT
- **ROLLBACK 범위**: 마지막 COMMIT 이후 변경만 취소

**헷갈리는 지점**
- SQL Server 는 DDL 도 트랜잭션 안에서 롤백 가능, Oracle 과 다름
- `ROLLBACK` 은 오류 없이 실행되고 취소할 변경이 없을 뿐

**보기별 판단**
- **A** (오답, 내 선택): DDL 자동 커밋을 놓쳐 INSERT 취소로 본 값
- **B** (정답): DDL 자동 커밋으로 INSERT 확정, 1행
- **C** (오답): 모든 문장 정상 실행, 오류 없음
- **D** (오답): INSERT 는 1번만 실행

**시험 팁** DML 뒤 DDL 이 끼면 그 앞까지 커밋된 것으로 계산

### 09-data_modeling

**오답 · B 선택, 정답은 A · 이행 함수 종속 제거는 3NF**

**정답 A 근거**
제2정규형은 복합 기본키의 일부에만 종속된 속성(부분 함수 종속)을 분리해 모든 일반 속성이 기본키 전체에 완전 함수 종속되게 함.

**핵심 개념**
- **부분 함수 종속**: 복합 기본키 일부만으로 결정되는 속성, 2NF 에서 제거
- **정규형 순서**: 1NF 원자값 > 2NF 부분 종속 제거 > 3NF 이행 종속 제거 > BCNF 결정자 후보키

**헷갈리는 지점**
- 이행 함수 종속 제거는 2NF 가 아닌 3NF
- 단일 컬럼 기본키면 부분 종속이 없어 1NF 이면 곧 2NF

**보기별 판단**
- **A** (정답): 부분 함수 종속 제거, 2NF 정의
- **B** (오답, 내 선택): 이행 함수 종속 제거는 3NF
- **C** (오답): 원자값·반복 그룹 제거는 1NF
- **D** (오답): 결정자 모두 후보키는 BCNF

**시험 팁** 정규형별 키워드: 원자값, 부분, 이행, 결정자
