# ISS-0319 완료 리포트: 구조화 해설을 세트당 1회 생성·저장하고, 미리보기 카드와 비모달 해설 시트로 개편

GitHub #521 개요 댓글 기준 (2026-10-18).

## 해결 방법
- 서버: 구조화 해설(판정은 서버가 DB 정답으로 생성, 정답 근거, 핵심 개념, 헷갈리는 지점, 보기별 판단, 시험 팁). 항목별 길이 상한·문체 규칙, 저장 전 검증(형식·정답 데이터와의 모순), 1회 재시도, 실패 시 기존 텍스트 폴백. 세트당 한 번 생성·저장하고 저장본을 즉시 응답, 없으면 "생성 중"을 돌려주고 백그라운드 생성. 프롬프트 버전이 바뀌면 옛 해설을 보여 주며 뒤에서 재생성.
- 새 API `GET /api/ai/choice-explanation`(READY / GENERATING / FAILED). 제출 기록이 없으면 400.
- 출시된 앱 호환: 기존 `diff-explain` 응답은 구조화 해설을 마크다운으로 그린 글로 유지.
- 해설 품질 하네스 `tools/explanation-harness/`.
- 앱·웹: 제출 직후 미리보기 카드(판정 + 근거 2줄 + 전체 보기), 텍스트 줄 모양 스켈레톤, 섹션 카드 순서의 전체 해설, 앱 드래그 비모달 시트·웹 오른쪽 패널/하단 시트, 세션 해설함(최근 20개). 시트가 열리면 미리보기 카드 숨김.
- 웹 하단 바: 측정된 바 높이로 여백, 배경 불투명.
- 운영 실측: 구조화 해설 1회 시도로 1.6~3.3초 생성, 운영 웹 약 2초 안 미리보기.

## 근본 원인 (확정)
이슈 노트 참조.

## 재발 방지
- 해설 문체가 섞인다("~합니다"와 명사형) — 프롬프트 v2 과제. 하네스 기록 샘플은 실제 Gemini 출력이 아니라 손으로 쓴 것.
- 백필은 10분마다 6세트, 그 전에 조회되는 세트는 요청 시점 생성.
- 해설 문장 속 보기 키(A~D)는 서버 키라 앱의 화면 표시 순번과 다를 수 있다. 판정 문구만 화면 라벨로 다시 만든다.
- 다크 모드·작은 화면 실측은 사용자 기기 테스트로 넘김.
- "다음 문제로 가도 시트 유지" 설계는 GitHub #538에서 바뀌었다.

## 교훈
(원본에 없음, 볼트 정리) LLM 결과를 요청 경로에서 동기로 만들면 대기가 사용자 체감으로 그대로 간다 — 미리 만들어 저장하고 상태(GENERATING)를 돌려준다.
