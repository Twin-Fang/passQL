# ISS-0188: 출시 전 리뷰에서 확인된 SSE 파싱, 로그인 유지, 막다른 화면 문제

GitHub #343 (원본: 이슈 본문과 댓글).

## 증상
출시 전 코드 리뷰(앱-서버 응답 대조, 앱 코드 정확성, iOS 심사 정책)에서 확인:
- 선택지 생성(SSE) 파싱 실패: Spring이 `event:status`처럼 콜론 뒤 공백 없이 보내는데 앱은 공백을 요구해 이벤트를 하나도 못 읽음 (핵심 풀이 흐름)
- 앱 시작 시 보안 저장소를 읽지 못하면(백업 복원, 키 유실) 앱이 켜지지 않음
- 오프라인·서버 5xx일 때 토큰 재발급이 실패하면 로그인이 지워짐
- 로그인·회원 탈퇴 중 예상 밖 오류가 조용히 사라짐, 탈퇴 중복 탭 가능
- SSE 스트림이 이벤트 없이 끝나면 선택지 로딩이 영원히 남음
- 풀이 화면 오류 시 재시도 수단 없음, 마지막 제출 후 완료 처리 중 연타 가능
- iOS는 앱을 삭제해도 키체인이 남아 재설치 후 이전 계정이 자동 로그인
- 오래된 토큰 요청이 늦게 401을 받으면 재발급을 한 번 더 함

## 재현 조건
위 각 상황(공백 없는 SSE 이벤트, 저장소 손상, 오프라인·5xx 중 재발급, iOS 재설치 등).

## 조사 기록
- 2026-10-06: 세 가지 병렬 리뷰 결과 중 확인된 문제를 수정(커밋 `541e706`).

## 근본 원인
SSE 파서가 RFC와 달리 공백을 필수로 봤고, 재발급 실패를 서버 거부와 일시적 오류로 나누지 않았다. 나머지 항목은 오류·빈 스트림 처리 누락.
