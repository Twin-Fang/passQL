# ISS-0381: 관리자 회원 목록·상세에 정렬·검색·메모·일괄 처리가 없음

GitHub #626 (원본: 이슈 본문; 완료 내용은 GitHub #611 통합 리포트 댓글).

## 증상
회원 목록이 최신순 고정이고 UUID 검색·상태별 집계가 없다. 회원 상세에 관리자 메모가 없고, 푸시를 보내려면 push 화면에 UUID를 붙여넣어야 한다. 제출·알림 탭 페이지네이션이 없고 작성 글·신고 이력 탭이 없다.

## 재현 조건
해당 없음 (기능 이슈).

## 조사 기록
- 2026-10-24: 관리자 화면만으로 운영(DB 직접 조회 없이)하기 위한 관리자 개선 묶음(GitHub #611~#631) 중 하나로 등록. 공통 조건: 관리자 변경 작업은 기존 `AdminAuditLogService`로 감사 로그, 서버 API 변경 시 `api-contract/openapi.json` 갱신까지 한 커밋.
- 작업 범위: 정렬 선택·UUID 검색·상태별 집계 요약, 체크박스 일괄 정지·일괄 푸시·목록 CSV 내보내기, 회원 상세 관리자 메모·'이 회원에게 푸시' 버튼·제재 사유 분류, 제출·알림 탭 페이지네이션·작성 글·신고 이력 탭.
- 2026-10-24: GitHub #611 통합 구현 보고서(PR #634, 운영 배포) 결과 — 회원 정렬·검색·집계·PRO 필터, 일괄 정지·푸시, 메모 완료. 이 이슈 자체에는 완료 댓글이 없어 완료 리포트는 #611 쪽에 있다.
- 주의(#611 리포트): 접속순 정렬은 `Specification`을 쓰는 `findAll`이 `Sort`의 `nullsLast`/`nullsFirst`를 지원하지 않아 500이 났다. 접속순 2종은 `MemberSpecification.orderByLastSeen`이 직접 정렬한다. `Sort`로 되돌리면 재발.
- 주의(#611 리포트): 회원 목록에서 일괄 푸시하면 회원마다 발송 이력이 1건씩 쌓여 푸시 화면 이력이 길어진다.
- 남은 일(#611 리포트): 목록 CSV 내보내기는 #612 남은 일에 묶여 있다(문제·회원·건의 목록).

## 근본 원인
기능 이슈. 해당 기능이 없었다(원본 「현재 문제점」 기준). 코드상 원인은 원본에 적혀 있지 않다.
