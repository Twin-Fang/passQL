# ISS-0304: 광고 도입(보상형·하단 배너) → Pro 회원 광고 숨김

GitHub #499 (원본: 이슈 본문, 취소·재오픈 댓글, Pro 광고 숨김 리포트 댓글, 후속 댓글). 현재 열림(재오픈, 라벨 작업중).

## 증상
- 원래 제안(2026-10-16): 기본 사용자 수익 수단과 크레딧 광고 충전 경로가 없음. 보상형 광고(원할 때만, 서버 검증 콜백, 하루 한도), 하단 배너(홈·문제 목록 탭만, 못 받아오면 접힘), 광고 단위 ID·노출 여부는 관리자 설정, ATT·UMP 적용, Pro 사용자 광고 없음.
- 재오픈 사유(2026-10-26): 광고 조건이 모바일·로그인 2개뿐(`ad_providers.dart`)이라 Pro 회원에게도 광고가 나온다. 이 이슈 범위는 Pro 광고 숨김만. 보상형 광고는 크레딧 명세 폐기로 범위에서 뺌.
- 후속(2026-10-27): 결제 스위치가 꺼져 있으면 서버가 모든 회원을 PRO로 내려줘, "프로면 광고 끔" 조건 때문에 아무에게도 광고가 나오지 않았다.

## 재현 조건
Pro 회원(결제 켜짐)이 모바일에서 로그인했을 때 광고 노출. 결제 스위치 꺼짐 상태에서 모든 회원에게 광고 미노출(첫 수정 후).

## 조사 기록
- 2026-10-26: 처음에는 명세 변경으로 취소했으나, Pro 광고 결함이 명세와 무관하게 남아 있어 다시 엶.
- 2026-10-26 리포트(PR #664, 릴리스 #666): `app/lib/presentation/providers/ad_providers.dart` 광고 허용 조건 3개(모바일, 로그인, Pro 아님). 등급을 모르면(로딩, 조회 실패, 회원 전환 중) 광고를 끔. 기존 `knownPlanProvider`·`isProProvider`(`GET /members/me/plan`)를 같이 봄(`isProProvider`는 모를 때 false라 로딩 중을 구분할 수 없어서). 전면 광고는 보여 주기 직전 조건을 다시 읽음. 테스트 `ad_providers_test.dart` 5가지, 앱 테스트 689개 통과.
- 2026-10-27 후속(PR #678): 결제가 켜져 있으면서 실제 프로인 회원에게만 광고를 숨김. 결제가 꺼진 동안에는 로그인한 모바일 회원 모두에게 광고. "결제 꺼짐 + PRO 응답" 판정 테스트 추가.
- 스토어: Android 1.54.1 프로덕션 심사 등록, iOS 1.53.6 심사 취소 후 1.54.1로 재제출(심사 전 iOS 1.51.1 출시). 원본: 두 스토어 심사가 통과해 사용자에게 반영되면 이슈를 닫는다.

## 근본 원인
frontmatter `root_cause`와 같음. (원본에 없음, 볼트 정리) 결제 꺼짐 상태의 PRO 응답은 [[DEC-0005-ship-with-billing-switch-off]]와 관련된 동작으로 보인다.
