# ISS-0388: README·스토어 문구·홍보 이미지에 문제 수(300문제 이상)가 남아 있음

GitHub #636 (원본: 이슈 본문과 진행 댓글 2개).

## 증상
사용자에게 문제량을 어디에서도 보여 주지 않기로 했는데(GitHub #609), 공개 문서와 스토어 문구에 "300문제 이상"이 남아 있다.

## 재현 조건
해당 없음. 남아 있던 위치(전수 조사): `README.md:48` 한눈에 보기 표, `app/docs/store/README.md:14` 작성 규칙 메모, `app/docs/store/descriptions/ios-full.txt:8`·`play-full.txt:8` 스토어 긴 설명, `app/tool/store_art/scenes.json:47` 홍보 이미지 헤드라인과 그 파일에서 생성되는 홍보 이미지.

## 조사 기록
- 2026-10-24: 작업 — 문구에서 문제 수 제거("SQLD 전 범위, 주제별로 차근차근"), 홍보 이미지 재생성(`render.py`), 스토어 반영은 별도(앱 배포·메타데이터 업로드는 사용자 요청 시).
- 2026-10-25: 스토어 콘솔 반영 — App Store Connect(iOS 1.46.5): 설명을 "■ 주제별로 차근차근" 새 설명으로 교체·`ios-full.txt`와 일치 확인, 스크린샷 3번은 심사 대기 중 잠겨 `심사에서 제거 > 3~7번 교체 > 다시 제출`(상태 다시 `심사 대기 중`, 심사 순서 초기화). Google Play: 긴 설명을 `play-full.txt`로 교체, 휴대전화 스크린샷 3~7번 `android-phone/03~07.png`로 교체, `검토를 위해 변경사항 2개` 전송.
- 2026-10-25: 확인 못 한 것 — Play 검토 통과 후 실제 스토어 화면. 홍보 이미지 7번 "하루 10문제"(`scenes.json` 76줄)와 1번 홈 캡처의 10문제는 오늘의 세트를 5문제로 줄여(GitHub #644) 다시 만들어야 함.
- 2026-10-25: 홍보 이미지 재생성(PR #659) — 원본 캡처가 옛 앱 화면(탭 5개)이라 7장 전부 현재 화면으로 다시 찍음. 홈 "오늘의 5문제", 7번 문구 "하루 5문제, 순위를 보며 꾸준히 이어 가요". 바뀐 파일은 `app/docs/store/promo/` 아래 `source/` 7장, `ios-6.3/01~07.png`, `ios-6.5/01~07.png`, `ios-6.9/01~07.png`, `android-phone/01~07.png`, `feature-graphic.png`. 스토어 재업로드 대상은 7장 전부와 Play 그래픽 이미지.
- 2026-10-25: 판단 필요로 남은 것 — 3번째 장(최신 경향)의 "최신 경향 문제 총 27개"는 앱 화면의 가짜 값인데 문제량 노출로 볼 수 있음. 스토어 콘솔 재업로드는 하지 않음(앱 심사 재제출이 필요해 별도 요청 시). 이슈는 열려 있다(라벨 `작업중`).

## 근본 원인
문제량 비노출 방침(GitHub #609) 이전에 쓴 문구·이미지가 남아 있었다. 그 밖의 원인 설명은 원본에 적혀 있지 않다.
