기능 이슈라 결함 원인은 없다. 통합 중 발견한 결함: 회원 접속순 정렬 500 — `Specification`을 쓰는 `findAll`은 `Sort`의 `nullsLast`/`nullsFirst`를 지원하지 않는다. 접속순 2종은 `MemberSpecification.orderByLastSeen`이 직접 정렬하도록 고쳤다.

## 재발 방지
- 회원 정렬을 `Sort`로 되돌리면 접속순 정렬 500이 재발한다. 단위 테스트와 컴파일을 모두 통과해 앱을 띄워 보기 전에는 발견하지 못했다.
- 웹 타입 재생성을 빼먹으면 React Build Check가 실패한다.
- 주의: 회원 목록 일괄 푸시는 회원마다 발송 이력이 1건씩 쌓인다. 임베딩 진행률은 서버 메모리 한 건이라 재시작 시 사라지고 DB의 RUNNING 기록은 다음 실행 때 FAILED로 정리된다.
- 미실행 검증: Slack 알림 실발송, 예약 푸시 스케줄러 실동작, 브라우저 JS 동작(diff·미리보기·모달·다크모드).
- 기존 실패 1건: `ChoiceSetEntityIntegrationTest.quizSession_저장과_조회`는 변경 전 main에서도 같은 외래키 오류로 실패.
- 남은 일: #619 구매 금액·통화(`StorePurchaseRecorder`에서 저장), #624 설정 키별 값 범위, #627 신고자 제재 바로가기(식별 정보 노출 정책 결정 필요)·댓글 관리, #631 2FA(TOTP)·비밀번호 변경 주기, #612 CSV 내보내기를 목록 화면(문제·회원·건의)에 적용(공통 유틸 `AdminCsvResponseWriter`는 있음), Chart.js·FullCalendar CDN 로컬 번들, 주석·이름 정리(여러 줄 문서 주석 17건 등).
