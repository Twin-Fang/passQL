# ISS-0188 완료 리포트: SSE 파서 표준화, 일시 오류 시 로그인 유지, 막다른 화면 제거

GitHub #343 완료 댓글 기준 (커밋 `541e706`, 2026-10-06). `## 개요` 형식 리포트는 없음.

## 해결 방법
- SSE 파서: `event:`/`data:` 접두사를 공백 유무와 관계없이 표준(RFC)대로 분리. 여러 줄 data, 주석, CRLF 처리 포함
- 보안 저장소 읽기 실패 시 로그인 화면으로 시작, Android 자동 백업 복원 차단
- 토큰 재발급은 서버가 거부(401/403)했을 때만 로그인 삭제. 네트워크 끊김·5xx는 유지
- 늦게 401을 받은 요청은 이미 갱신된 토큰으로 바로 재시도
- 로그인·탈퇴의 예상 밖 오류를 문구로 안내, 탈퇴 중 화면 잠금
- 이벤트 없이 끝난 SSE 스트림은 재시도 가능한 오류로 전환
- 풀이 화면 로딩 실패 시 "다시 시도"·"홈으로", 마지막 제출 후 완료 처리 중 잠금
- iOS 재설치 시 키체인에 남은 이전 로그인 삭제

## 근본 원인 (확정)
이슈 본문의 항목별 원인과 같다 (SSE 공백 요구, 재발급 실패 구분 없음, 오류 처리 누락).

## 재발 방지
분석 0건, 테스트 146개 통과. 2026-10-07 댓글: 테스트로 고정, 앱 테스트 147개 통과.
이번에 하지 않은 것: Apple 로그인 버튼 공식 위젯(`SignInWithAppleButton`) 교체(거절 가능성 낮음), 닉네임 신고 수단(서버 `NICKNAME_FORBIDDEN` 필터는 있음, 심사 메모에 운영자 조치 기재), 풀이 중 뒤로가기 확인·백그라운드 복귀 상태 보존, 가입 제공자 세션 저장, `GET /exam-schedules/selected` 빈 200 본문 dio 동작.

## 교훈
(원본에 없음, 볼트 정리) 선택지가 끝없이 로딩되면 SSE 접두사 파싱(콜론 뒤 공백)과 빈 스트림 처리부터 본다. 토큰 재발급 실패는 서버 거부일 때만 로그아웃한다.
