# DEC-0350: 기출 복원 문항은 공개 복원 수준이 아니라 실제 시험 수준(너무 짧지도 과하지도 않게)으로 다시 쓴다

GitHub #1155.

## 문제 정의 (Context)
공개 복원은 응시자 기억이라 지문·표·보기가 줄어든 판이고, 사용자(60회 응시자)는 실제 시험이 훨씬 어려웠다고 했다. 2차로 난이도를 크게 올렸더니 유형 조사(후기 135편, 복원 300문항 집계)상 일부가 실제보다 과했다. 사용자 요구: 너무 짧게도, 과하게도 만들지 않는다.

## 결정 (Decision)
- 복원에서 믿는 것은 회차·번호별 출제 개념과 판단 사실뿐. 길이·표 크기·보기 구성·난이도는 아래 기준으로 맞춘다. 정답은 Oracle 실행으로 확정.
- 회차당 기준: 지문 SQL 보통 5~12줄(13~20줄 3~6개, 20줄 초과 0, 1~4줄 5개 안팎), 표 문항당 1~2개(최대 3) 보통 4~7행(최대 10행), 2과목 함정 1개·2개 반반(3개 이상 5개 이하), NULL 은 표 문항의 30~40%, 모두 고르기는 진술 3개로 1~3개, 하나만 다른 것 4개 이상, 여러 문장 차례 실행 1~3개, 오류 고르기 2개 안팎, 결과 표 보기 0~2개, 새 유형(같은 식 고르기, 짝짓기, GROUP BY 거꾸로 맞히기) 1~2개, 결과 추적형 풀이 2~3분.
- 길이를 꾸미지 않는다(줄바꿈만 늘리기, 결과에 영향 없는 조건 추가 금지). 모자라면 모자란 채로 둔다.
- 난이도 표기는 실제 내용대로(표기만 올리지 않음).
- 기준 원본: `docs/sqld-research/difficulty-uplift-guide.md` 「보정」 절, 근거 `question-type-catalog.md`.

## 검토한 대안 (Alternatives)
- 공개 복원 수준 유지(1차 판): 실제보다 쉽다는 사용자 증언으로 버림.
- 전 문항 함정 2개 이상·SQL 8~20줄·표 6~10행(2차 판): 유형 조사상 실제보다 과해 보정.

## 결과 (Consequences)
**긍정**: 실제 시험에 가까운 연습. **부정**: 실제 줄 수·행 수는 시험지가 회수돼 누구도 직접 재지 못해 기준은 추정이다.

## 영향 범위 (Scope)
기출 복원 회차 문항(45~63회), 연구 폴더 문항 원본·지시서, 앞으로 추가할 회차.
