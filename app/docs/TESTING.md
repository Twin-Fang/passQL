# 앱 테스트 환경 (#944)

앱을 실제로 띄워 확인할 때의 기기 준비, 확인 표, 로그 보는 곳, 결과 기록 방법.
코드 테스트(규칙·계약·핵심 판정)는 `app/CLAUDE.md` 「규칙 테스트」를 따른다. 기능 테스트 코드는 두지 않는다 (#680).

## 1. 기기와 빌드

| 대상 | 기기 | 빌드 | 비고 |
|---|---|---|---|
| iOS | 시뮬레이터 1대 (iPhone 16 Pro 등) | `flutter run -d <udid> --debug --no-resident` | 한글 경로 worktree 는 iOS 빌드가 실패한다. 영문 경로 임시 worktree 에서 빌드 |
| Android | 에뮬레이터 1대 (Play 스토어 포함 이미지) | `flutter run -d emulator-5554 --debug --no-resident` | 로컬에는 릴리스 서명 키가 없어 `--release` 는 실패 (디버그로 확인) |
| 실기기 | 사용자 폰 | 이슈에 `@projectops app build <브랜치>` 댓글 > Firebase App Tester(Android)·TestFlight(iOS) | 제공자 앱(카카오톡·네이버 앱)이 깔린 실제 경로 확인용 |
| 웹 | Chrome 390px·1280px | 운영 `passql.vercel.app` | 배포 뒤 확인 |

- 디버그 빌드도 **운영 서버**에 붙는다. 시험용 계정으로만 확인한다.
- 디버그 빌드는 AdMob 검사 창(native ad validator)이 화면 아래를 가린다. Dismiss 로 닫고 진행.
- 기기는 pro-launch `device acquire` 로 빌리고 끝나면 `device release` (다른 세션과 같이 쓴다).

## 2. 소셜 로그인 확인 표

같은 「로그인」 버튼도 **기기에 제공자 앱이 깔렸는지**에 따라 다른 길로 간다. 한 길만 보고 통과로 치지 않는다.

| 제공자 | 앱 설치 시 | 앱 없을 때 | 웹 |
|---|---|---|---|
| 카카오 | 카카오톡으로 전환 | 카카오 계정 웹 로그인 | 웹 로그인 > 서버 코드 교환 |
| 네이버 | **네이버 앱으로 전환** (#942 에서 실패 확인) | Chrome 로그인 화면(Custom Tab) | 웹 로그인 > 서버 코드 교환 |
| Google | 시스템 계정 선택 | 시스템 계정 선택 | Google 웹 |
| GitHub | 인증 세션(웹) | 인증 세션(웹) | 웹 + PKCE |
| Apple | 시스템 (iOS 만) | - | Apple 웹 |

확인 칸 (매 로그인 관련 변경마다)

| 플랫폼 \ 경로 | 카카오톡 | 카카오 웹 | 네이버 앱 | 네이버 웹 | Google | GitHub | Apple |
|---|---|---|---|---|---|---|---|
| iOS | | | | | | | |
| Android | | | | | | | 해당 없음 |
| 웹 | 해당 없음 | | 해당 없음 | | | | |

- 「앱 설치」 칸은 제공자 앱을 깐 기기(실기기 또는 앱을 깐 에뮬레이터)에서만 채운다.
- 에뮬레이터 저장 공간이 모자라면 제공자 앱이 깔리지 않는다 (2026-11-07 기본 에뮬레이터 여유 약 800MB). 저장 공간을 늘린 에뮬레이터를 따로 두거나 실기기로 확인.

## 3. 첫 실행 흐름 반복

개발자 도구(디버그·테스트 빌드만, #819)의 「첫 실행 상태로」가 첫 실행 판단 기록(설치 표식, 알림 안내, 스토어 평가 요청, 최근 로그인 제공자 등)을 지운다. 「온보딩 다시 보기」는 다음 실행에 온보딩부터.

확인 순서: 첫 실행 상태로 > 앱 다시 시작 > 로그인 > 온보딩 4장 > 오늘의 세트 첫 문제 > 축하 화면 > 홈 > (두 번째 실행 또는 결과를 본 뒤) 알림 권한 안내 시트

## 4. 결제 확인

전체 결제 스위치(`billing.android.enabled`)는 켜지 않는다. 관리자 앱 설정 `billing.preview_member_uuids` 에 넣은 시험 계정만 결제 켜짐으로 동작한다. 실제 결제 시험은 iOS Sandbox 계정, Android 라이선스 테스터로 한다. 세팅과 시나리오는 #941.

## 5. 로그 보는 곳

| 무엇 | 어디서 |
|---|---|
| 앱 로그 (에뮬레이터) | `adb logcat` 에서 `flutter`, `NaverIdLogin` 등 태그 |
| 앱 로그 (실기기) | 앱 설정 > 의견 보내기 (진단 정보 + 최근 앱 로그 첨부) > 관리자 건의사항에서 로그 받기 |
| 서버 요청·오류 | 관리자 모니터링 「최근 서버 오류」(요청 ID), 자세한 스택은 서버 컨테이너 로그에서 요청 ID 로 검색 |
| AI 호출 | 관리자 AI 사용량·통계, 모니터링 |
| 스토어 심사 | `PROJECT-FLUTTER-IOS-ASC-STATUS` 워크플로 (ASC 버전 상태 조회, 읽기 전용) |

로그인 실패가 서버 로그에 없으면 앱 SDK 단계에서 끝난 것이다 (#942: 네이버 SDK `no_catagorized_error`, 서버 요청 없음).

## 6. 결과 기록

- 해당 이슈 댓글에: 기기·OS·빌드·계정 종류, 어디까지 됐는지, 캡처(라이트·다크), 막히면 오류 화면·앱 로그·서버 로그 발췌
